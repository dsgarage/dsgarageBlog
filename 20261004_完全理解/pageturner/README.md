# pageturner — Keynote 自動めくり + Apple Watch 通知

2026-10-04 の 10 分発表用。時間表（`schedule.json`）どおりに Keynote のスライドを自動でめくり、めくる前に [ntfy](https://ntfy.sh) で通知を送ります。通知は iPhone の ntfy アプリに届き、Apple Watch へミラーされて振動します。watchOS アプリは使いません。

- `keynote_timer.py` … 本体（Python 3 標準ライブラリのみ。pip 不要）
- `schedule.json` … 時間表（`台本骨子.md` の時間配分に合わせた 1 章 = 1 スライドの仮の秒数、合計 600 秒）

## 通知の中身

| タイミング | 通知 | 優先度 |
|---|---|---|
| めくる `warn_before_sec` 秒前 | 「あと10秒 → 次: <次のタイトル>」 | high |
| 全体の残り 1 分 | 「残り1分」 | high |
| 最後のスライドの時間到達 | 「終了時間です」 | urgent |

最後のスライドはめくりません（「あと10秒」も送りません）。「終了時間です」を送るとスクリプトは終わり、スライドショーはそのまま残ります。

## 準備（1 回だけ）

1. **トピック名を決める**: `schedule.json` の `ntfy_topic` は ntfy.sh の公開サーバー上の名前で、名前を知っている人は誰でも読めて送れます。推測されにくいランダムな文字列にしておきます（サンプルの値をそのまま使っても構いませんが、自分で作り直すなら `python3 -c "import secrets;print('talk-'+secrets.token_hex(8))"`）。
2. **iPhone に ntfy アプリを入れる**: App Store の「ntfy」をインストールし、通知を許可します。アプリで「+」→ サーバーは `ntfy.sh` のまま → 上のトピック名を入力して購読します。
3. **Apple Watch へのミラー**: iPhone の Watch アプリ → 通知 → ntfy を「iPhone を反映」にします。Watch に届くのは **iPhone がロック中（画面が消えている）で、Watch を腕に着けているとき** だけです。iPhone の画面を見ている間は iPhone 側にしか出ません。
4. **集中モード**: 発表中に集中モード（おやすみモード等）を使うなら、ntfy を「通知を許可」に入れておきます。入れないと振動しません。
5. **届くか確かめる**:
   ```sh
   python3 keynote_timer.py schedule.json --test-notify
   ```
   `HTTP ステータス: 200` が出て、iPhone（ロック中なら Watch）に「テスト通知」が届けば準備完了です。
6. **Keynote の自動操作の許可**: 初回の本番実行で「"ターミナル" が "Keynote" を制御しようとしています」と出たら「OK」を押します。拒否してしまったときは システム設定 → プライバシーとセキュリティ → オートメーション → ターミナル → Keynote をオンにします。

## 使い方

```sh
cd pageturner
python3 keynote_timer.py schedule.json            # Keynote の前面の書類を 1 枚目から開始して自動めくり
python3 keynote_timer.py schedule.json --no-start # 既に再生中のスライドショーをそのまま使う
```

| オプション | 内容 |
|---|---|
| `--no-start` | スライドショーを開始しない（再生中でなければエラーで止まる） |
| `--dry-run` | Keynote を操作せず、時間表どおりの流れ（めくり・通知の予定時刻）をログに出す。通知も送らない |
| `--dry-run --notify` | Keynote は操作せず、通知だけ実際に送る（Watch の振動リハーサル） |
| `--speed N` | 時間を N 倍速で進める（例 `--dry-run --speed 20` で 10 分を 30 秒で確認） |
| `--test-notify` | 通知を 1 件送って終了 |

開始前に 3 秒カウントダウンします。ターミナルには「現在スライド/総数・タイトル・このスライドの残り・全体の経過/残り」が 1 行で上書き表示されます。

### キー操作

- `p` … 一時停止 / 再開（止めている間はめくらず、通知も送りません。経過時間も止まります）
- `q` … 終了
- `Ctrl+C` … 中断

**キーはターミナルにフォーカスがあるときだけ効きます。** スライドショーを始めると Keynote が前面に出るので、ディスプレイが 1 枚だとキーは効きません。外部ディスプレイに投影し、手元の画面でターミナルをクリックしておくと使えます。

### 手動でめくったとき

Keynote の現在スライド番号を 0.5 秒ごとに見ています。話者が `→` / `←` で手動で移動したら、そのスライドの秒数で計り直します（時間表のずれに追従します）。自動めくりは、表示されてからそのスライドの `sec` が経ったときに行います。

「残り1分」は、スライドごとの計り直しとは関係なく、**開始からの経過時間**（一時停止中は数えない）で判定します。

## 当日の手順

1. Mac を電源につなぎ、スリープしない設定にする。Wi-Fi（またはテザリング）がつながっているか確認
2. iPhone: ntfy の購読を確認し、集中モードの許可を確認。発表中はロックしてポケットへ（Watch に届くのはロック中だけ）
3. Keynote で発表用の書類を開く（ほかの書類は閉じておく。前面の書類が対象になります）
4. `python3 keynote_timer.py schedule.json --test-notify` で Watch に届くことを確認
5. 出番になったら `python3 keynote_timer.py schedule.json` を実行 → 3 秒後にスライドショー開始

## トラブル時の対処

| 症状 | 対処 |
|---|---|
| 「Keynote が起動していません」「書類が開かれていません」 | Keynote で書類を開いてから再実行。AppleScript で作っただけで画面に出ていない書類は、Keynote ごと自動で終了することがあります |
| 「スライド枚数と時間表の枚数が一致しません」 | `schedule.json` の `slides` を Keynote の枚数に合わせる。そのまま続けるなら `y`（ターミナル以外から起動した場合は確認できないので中止します） |
| 「osascript が応答しません」 | 自動操作の許可ダイアログが裏に出ていないか確認（準備 6） |
| 通知が届かない | `--test-notify` の HTTP ステータスを確認。200 なのに届かないなら、トピック名の打ち間違い・iPhone の通知設定・集中モード・iPhone がロックされていない（Watch に出ない）を順に確認 |
| 通知の送信に失敗する（ネットワーク断） | ログに `[通知失敗]` と出るだけで、めくりは止まりません |
| めくりがずれた | `→` / `←` で手動で合わせれば、そこから計り直します。止めたいときは `p` |
| スクリプトが止まった / 落ちた | スライドショーはそのまま残るので、`--no-start` で再実行すれば、今のスライドを最初から計り直して続けます。全体の経過は 0 から数え直すので「残り1分」は実際より遅れます |
| Esc でスライドショーを終えた | スクリプトは「スライドショーが終了したので停止します」と出して終わります |

凡例: **[話者]** = 講演者の意見・自社判断、**[事実]** = Blender の一般的な仕様・機能、**(要確認)** = 聞き取り不明確または講演で明示されていない補足。

## 1. 方針・判断基準

- **[話者]** 背景を「動かす」（背動）カットが多い案件では、カメラマップより完全な 3D 空間を組む。カメラマップは移動範囲が広がるほど描き素材が増え、素材間の誤差調整が難しくなるため
- **[話者]** 約 400 カット・半数近くが背動という規模では、プロシージャル（シェーダーノード、ジオメトリーノード、手続き的アニメーション）を前提に設計する。ペイント中心では回らない
- **[話者]** 良い CG 背景は良いモデルから生まれる。キャラクターとの縮尺が正確で、360 度どこから見ても破綻しない「箱庭モデル」を作る。モデル・ライティング・レンダー設計が甘いと後工程の修正が膨らむ
- **[話者]** 仕事では車輪の再発明をしない。既存アセット・アドオン・既存ノードを先に探し、浮いた時間をルックの追い込みに使う。ノードを一から組むのは学習目的なら有効
- **[話者]** 選定の基準は「どのアドオンが優れているか」ではなく「実現したいルックに何が必要か」
- **[話者]** 物理的に正しいシミュレーションより、必要な画を作るために使える機能をどう組み合わせるかを優先する
- **[話者]** デジタル空間など CG と相性の良い設定では、ルックも CG らしさを生かす方向で設計してよい

## 2. 背景美術との分業・ハイブリッド

- **[話者]** 3D 側がモデル制作（とベースのレンダリング）までを担当し、最終仕上げを美術（描き）スタッフが行う分業にすると、美術側が造形・パース補完の基礎作業から解放される
- **[話者]** Blender 初心者の背景スタッフには、レンダー素材を Photoshop で合成して仕上げるハイブリッドから始めることを推奨
- **[事実]** レンダーパス（View Layer Properties > Passes）でベースカラー、影、反射、AO などを個別に出力できる。Cycles では Diffuse/Glossy の Direct/Indirect/Color、Ambient Occlusion、Shadow Catcher 等（講演で挙げた要素は「ベースカラー・陰影・反射・AO(要確認)」）
- **[話者]** 反射光・環境光は描きでは経験則頼みになりやすい。3D で物理計算した結果を「色のシミュレーション」として参照すると、観察だけでは見つけにくい色の関係が得られる
- **[話者]** 遠景（眼下の街並みなど）は 3D でモデリング・レンダリングした画像を美術が仕上げ、天球（スカイドーム）に貼る運用が使える

## 5. スパイラル柱（モディファイアスタック）

目的: 回転しながら昇る螺旋状の骨組みの柱。粒子の発生源にもする。

作業画面（10:45:12 のフレーム）で確認できたスタック順: Array → SimpleDeform.001 → Wireframe → Lattice → Boolean → Boolean.001 → GeometryNodes（粒子生成の GN はモディファイアスタックの最後尾）。

1. 元形状はシンプルな四角形（面 1 枚、要確認）
2. **Array**: 縦方向に連続させる。長さはカーブ（スプライン）で制御できるようにしている → Array の Fit Type = Fit Curve 相当と推定 (要確認)
3. **Simple Deform**（Twist）: 全体をねじって螺旋状にする
4. **Wireframe**: 面を骨組み状のフレームに変換
5. **Lattice**: シルエットを変形し、上に向かって広がる形にする
6. **Boolean ×2**: 上下の余分をカットし、使う範囲だけ残す
7. アニメーション: 柱全体を回転させながら上方向へ移動 → 螺旋が回りながら昇って見える

- **落とし穴と対策 [話者]**: 縦に長い柱を丸ごと粒子の発生源にすると、柱が上昇するにつれて発生面積が増え、粒子量も増える。Boolean で発生範囲を固定の高さに切り出すと、柱を動かしても発生量が一定になる（Boolean を「形状カット」と「発生源の面積固定」の二役で使う）
- **音に合わせた回転 [話者]**: ライブ音源を解析して F カーブに変換し、回転速度の強弱に使う。レーザーライトはリグを組み、同様に動きと光量を音に同期
  - Blender にはグラフエディターから音声の振幅を F カーブにベイクする機能がある（メニュー名は版により「Sound to Samples」「Bake Sound to F-Curves」等、要確認）。本作で使った機能名は講演で未言及 (要確認)

## 6. ジオメトリーノードによる自作パーティクル（柱から出る粒子）

採用理由 **[話者]**: 後工程で素材ごとに分けて管理する処理（ブック分け）が必要だったため、標準パーティクルシステムからジオメトリーノードに変更。

1. **Distribute Points on Faces**: 柱表面（Boolean でカット済み）に点を発生
2. 各点にランダムな初期速度（Velocity 属性）を持たせる（Random Value）
3. **Simulation Zone** 内で、毎フレーム 位置 += 速度 で更新（Set Position）
4. 各点に **Age** 属性を持たせ、Simulation Zone 内で毎フレーム加算
5. Age が閾値を超えた点を **Delete Geometry** で削除 → 寿命の再現
6. **Instance on Points**: 複数の形状をインスタンス配置。形状の選択・スケールにランダム変化
   - 作業画面で確認できたノード: Named Attribute（Float, 名前 `Age`）→ Math Add（+1.0）、Math Greater Than（Threshold 5.0、解説用の値）、Random Value（Float, Min 1.0 / Max 2.0）、Vector Rotate（Axis Angle）、Random Value（Vector）、Collection Info（`shape_sp`、Separate Children と Reset Children を ON）、Instance on Points の Pick Instance / Instance Index / Rotation / Scale 入力
   - 形状の切り替えは Collection Info（Separate Children）＋ Pick Instance で、コレクション内の子オブジェクトからランダムに選ぶ構成と読める（接続の細部は要確認）
- 本番データでは、この後にブック分け用の工程がもう 1 段ある（講演では省略）**[話者]**
- **注意 [事実]**: Simulation Zone で毎フレーム新しい点を発生させる場合、発生分を Join Geometry で既存点に合流させる構成が一般的（講演での構成は要確認）

## 7. 灯籠: 水面を流れ、縁で上昇する（Blender 4.2 時点の制約前提）

背景 **[話者]**: 3ds Max の Particle Flow ならイベントで簡単に切り替えられる内容。Blender 標準パーティクルでは条件分岐の制御が難しく、Python が必要になりそうだったため、ジオメトリーノードで作成。

1. 灯籠用のポイントを生成し、**Simulation Zone** で毎フレーム位置を更新
2. 流れる動き: **Random Value** で点ごとにわずかに異なる移動量を作り、Y 方向へ少しずつ移動（速度のばらつきで一斉移動感を消す）
3. 縁での切り替え: 「縁に到達したイベント」を作る代わりに、各点から下向きに **Raycast** し、水面メッシュに Hit する間は流れる、Hit しなくなったら **Switch** で移動方向を上昇に切り替える
4. 上昇速度にもランダム差をつける
5. 最後に **Instance on Points** で灯籠モデルを配置（モデルを直接動かさず、点で挙動を作ってから最後にインスタンス化）

### 疑似コリジョン（試したが今回は不採用寄り）

- **[事実]** ジオメトリーノードには標準のコリジョン機能がない（4.2 時点）
- 手順 **[話者]**: **Index of Nearest** で最も近い点を探す → **Evaluate at Index** でその位置を取得 → **Distance**（Vector Math）で距離を計算 → 閾値より近ければ相手から離れる方向へ位置を補正。水面上なので Z には押し出さず XY のみ補正。1 回では解消しないため **Repeat Zone** で複数回繰り返す
- **落とし穴 [話者]**: 補正を弱くするとめり込みが残り、強くすると接触した灯籠が大きく弾かれたり分裂したように見える。摩擦・質量・反発係数の概念もない。灯籠数やリピート回数を増やすと重くなる
- **判断 [話者]**: 完全な当たり判定を目指さず、灯籠の数・配置・移動量を含めて「画として自然に見える」ことを優先して調整する

## 9. プリビズからの引き継ぎ

- **[話者]** 演出段階のプリビズでメッシュがかなり作り込まれている場合、3D 背景側の作業はシェーディング中心になる。ただしメッシュ構造やライティングはそのまま使えないことがあり、アーティストに渡す前にモデル整理とルック調整を入れる
- **[話者]** プリビズが Blender で作られていると、レンダー用モデルへの移行とレンダリングがスムーズ
- **[話者]** カメラがステージを 360 度回るカットでは、キャラクターとの前後関係に合わせたブック分けが標準パーティクルでは難しい → ジオメトリーノードで作り直した
- **[話者]** 床の絵が変化する演出は、After Effects で作った連番素材をテクスチャとして貼り込む（Image Texture ノードの Image Sequence を使ったと推定、要確認）
- **[話者]** 発光感が弱く見える同系色の多いステージでは、シェーディング側で発光を強める調整をした

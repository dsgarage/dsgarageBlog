# S4 アニメルックのつくりかた: Skill 化用メモ

凡例: 【話者】= 登壇者・司会の意見や実践 / 【事実】= Blender 等の一般的な仕様 / (要確認) = 聞き取りが不明確
前提: デモ画面の表示は Blender 4.5.3 LTS（グリースペンシルは 4.3 以降の新実装）

## A. 線（グリースペンシル・ラインアート）

1. 【話者】Solidify＋バックフェースカリングの輪郭線は線幅が均一で手描き感が出にくい。手描き風を狙うならグリースペンシルのラインアートを使う
2. 【事実】オブジェクトモードで Shift+A → Grease Pencil → Collection Line Art を追加すると、対象コレクションのメッシュ輪郭から線が自動生成される（出力は「LineArt」系の GP オブジェクト）
3. 【事実】Line Art モディファイアーの Line Radius で線の太さを決める
4. 【話者】Edge Types の Crease Threshold は 138° 前後。180° に近づけるほどわずかな角度の辺にも線が出て、ポリゴン割りが見えてしまう。ビューポートで見ながら値を探る
5. 【話者】髪は Intersections をオフ。パーツ同士の交差線が出ると 3D らしさが目立つ
6. 【話者】線色はラインアートのマテリアルの Base Color で設定。明るいグレーの髪には淡いグレー、顔は黒の別マテリアル
7. 【話者】Subdivide モディファイアー（レベル 2 程度）を Line Art の直後に置き、カールした髪の線のカクつきを取る
8. 【話者】Thickness モディファイアーの値 0.3 程度（係数の意味で使用、要確認）。Influence → Custom Curve を山なりにすると始点・終点が細くなり「入り抜き」ができる。カーブの左右を下げるとそれぞれの端が細くなる
9. 【話者】Thickness の入り抜きは GP オブジェクトのプロパティ側ではなくモディファイアーで行う
10. 【話者】Simplify モディファイアーを Mode = Sample、Length を非常に小さく（0.01、単位は mm/cm で発言が揺れている。要確認）してポイントを再サンプリングする。見た目はほぼ変わらないが、次の Noise を効かせる下準備
11. 【事実】ポイント数が少ないとノイズ系の変形が効かない。ジオメトリーノードで Resample Curve してからノイズをかけるのと同じ考え方（司会の補足）
12. 【話者】Noise モディファイアー: Position は低め（画面では 0.00 表示、要確認）、Strength 0.1、Thickness 0.1、Noise Scale 0.600。項目名は画面で確認済み、Strength と Thickness の小数以下は画面が切れていて要確認。位置と太さの両方が揺らぎ、にじみのような凹凸が出る
13. 【話者】スタック順は Line Art → Subdivide → Thickness → Simplify → Noise（デモ画面で確認）。Thickness を Subdivide より上に置くとカクついたまま細るのでは、と話者が推測（未実演）。順序で結果が変わる点に注意
14. 【話者】拡大しないと見えない差でも画面全体の空気感が変わる。微調整を惜しまない

## B. 線を出す／消す場所の制御

15. 【話者】顔用は髪用のラインアートを複製し、対象コレクションを顔の入ったコレクション（例 body）に変更。線を細くし、黒マテリアルを当て直す
16. 【話者】顔メッシュに新規頂点グループ（例 Group03）を作り、Weight Paint で線を消したい部分（白目・肌など）を塗る。ツール設定の Symmetry X をオンにすると左右同時に塗れる
17. 【話者】ラインアート GP オブジェクトの Data プロパティにも頂点グループ（デモでは eye_mask。画面で確認）を作る
18. 【事実】Line Art モディファイアーの Vertex Weight Transfer で Filter Source = メッシュ側の頂点グループ名、Target = GP 側の頂点グループ（eye_mask）を指定すると、ウェイトが線に転送される
19. 【事実】Add Modifier → Color → Opacity を追加し、Influence → Vertex Group = eye_mask、Opacity Factor = 0 にすると塗った部分の線が消える（デモ画面の Mode は Stroke & Fill）
20. 【話者】ウェイトを中間値（0.5 前後）で塗ると線が半透明になる。作品では口の中央の線を少し透かすのに使用。完全に消す／途切れさせる／薄くするをウェイトで描き分ける

## C. 影・ハイライト・色管理・出力

21. 【話者】顔・髪の影とハイライトはライティングではなくテクスチャに描き込む。カメラを固定し、その視点から見える範囲だけ描く（カメラを回すと破綻する前提の割り切り）
22. 【話者】シェーダーは Image Texture の Color を Material Output の Surface に直結するだけ（何も挟まない）
23. 【事実】Blender 4.x の View Transform 既定は AgX で、テクスチャの色がそのまま表示されない。Render Properties → Color Management → View Transform = Standard にする
24. 【話者】View Transform の変更は作業の最初に行う。作り込んだ後に変えると色味が全部変わる（司会も同意）
25. 【話者】最終出力は通常レンダーではなく View → Viewport Render Animation。低スペック PC でのコスト削減が目的
26. 【事実】Shader to RGB は EEVEE 専用。Cycles では使えない。影の中だけを加工するようなセルルックは EEVEE 前提になる

## D. シェーダーを組む場合（マグカップの例）

27. 【話者】Image Texture → 色調整ノード（色相・彩度・明度系、ノード名要確認）で色を整える
28. 【話者】影: Diffuse BSDF → Shader to RGB → Color Ramp で段階化 → Mix Color（Darken／比較（暗））でテクスチャと合成
29. 【話者】Darken を選んだ理由は、乗算などより暗くなり方が濁らないため。【話者・司会】暗い方を採って情報量を潰す合成はセルルックのデフォルメと相性が良い
29b. 【話者】デモ画面の Mix の Factor は Darken が 0.329、Add が 0.182 前後に見える（画面が小さく要確認）。影もハイライトも Factor で弱めて重ねている
30. 【話者】ハイライト: Glossy BSDF → Shader to RGB → Color Ramp → Mix Color（Add）で上乗せ。陶器の縁にキラリとした白が乗る
31. 【話者】ライトの角度で BSDF 由来の影・ハイライトが変わるので、ライティングを探りながら調整する。Mix の Factor で強さを後から詰める（Photoshop のレイヤー合成の感覚）

## E. テクスチャ制作（Illustrator）

32. 【話者】UV のスナップショットを下に敷き、図形（パス）を置いてテクスチャを組み立てる
33. 【事実】Illustrator の 効果 → パスの変形 → ランダム・ひねり で形を崩せる。アピアランスパネルに積まれ、後から数値変更・オンオフ・重ねがけができる（Blender のモディファイアースタックに相当）
34. 【話者】目の輪郭や髪のハイライトは同形のパスにパラメーター違いのランダム・ひねりをかけ、手ブレ・筆のような揺らぎを出す
35. 【話者】パスにブラシ（鉛筆調のブラシなど）を適用してガタガタのタッチを付ける。目の細部、頬の赤み、涙の跡、服のしわ、首元のラインに使用。ブラシの種類でストローク方向の出方が変わる
36. 【話者】ロゴなどの文字はアウトライン化してから歪ませる
37. 【話者】ベクターなので寄っても荒れない。出力時に必要な解像度を決めて書き出す
38. 【話者】広いキャンバスをリファレンスボード（PureRef 的）として使い、カットごとの瞳バリエーションを並べて比較・採用する

## F. 背景（プロジェクションマッピング）

39. 【話者】背景はモデリングせず、イラストを板ポリや箱に投影する（マットペイント的な考え方）。一人制作でキャラクターに時間を回すため
40. 【話者】投影前にイラストのカメラ焦点距離、カメラの床からの高さ、奥の対象（ドア）までの距離、通路の幅、天井高が必要
41. 【話者】Claude にイラストを解析させて寸法の目安を出す。スライドの初期値は奥行き 380cm、幅 100cm、高さ 240cm、カメラ高 105cm。値は正確ではないので初期値として使い、下絵合わせ後の箱はデモ画面で 142×380×273cm になっていた。カメラの Focal Length は画面上 28mm
42. 【話者】焦点距離がずれる場合は、Blender のカメラビューのスクリーンショットを Claude に送ってイラストと比較させ、値を詰めていく
43. 【事実】カメラの Object Data → Background Images にイラストを読み込むと、カメラ視点で下絵として重ねられる
44. 【話者】下絵に合わせて箱の壁・天井を動かして一致させる
45. 【話者】箱に Subdivision Surface を Simple で高い分割数にして適用する。頂点が少ないと投影テクスチャが対角線方向に歪む
46. 【事実】カメラビューで全頂点を選び UV → Project from View を実行すると、カメラ視点どおりに画像が貼られる
47. 【事実】Project from View は投影時の視点に依存する。カメラを大きく動かすと隠れていた面や引き伸ばしが見えるため、動きは前進など小さめに留めるのが無難（一般的な注意。デモでは前進＋手ブレ）
48. 【話者】ドアなど動かしたい部分は別オブジェクトで作り、同様に投影してスライドさせる
49. 【話者】手ブレはアドオン Camera Shakify で付ける

## G. ツール構成・運用

50. 【話者】使用ツール: モデリング Blender、テクスチャ Illustrator（補助に Photoshop・生成 AI）、リグ Rigify、髪の揺れ Wiggle 2（表記要確認）、レンダー EEVEE、コンポジット After Effects（グレア・色収差だけ Blender のコンポジター。色収差は要確認）
51. 【話者】制作期間約 7 か月（脚本・絵コンテ 1、キャラモデリング 1、シーン構築・アニメーション 4、コンポジット・音 1）。平日 2 時間＋週末
52. 【話者】音楽は Artlist など（Musicbed、Epidemic Sound、Soundstripe）を普段から流し聞きしてストックしておく
53. 【話者】服の UV 展開図を AI に渡し「スペキュラーの色だけ足して」と頼むと反射部分だけを描き足してくれる。UV だけ渡して着色も可能
54. 【話者】モデルチェック用の Python スクリプト（画面の ModelCheck パネル）を Claude に作らせて自分専用ツールにしている（発言者の聞き分けは要確認。パネルは登壇者の Blender に表示）
55. 【話者】AI による UV 着色は継ぎ目などに多少の修正が必要。最初のあたりとして使う
56. 【司会】ラフを AI に見せて最終レンダリングのイメージを出してもらい、方向性を早めに見通すのに使える
57. 【話者】セルルックを選ぶ理由（スライド）: 一人制作のコストを下げたい、フォトリアルよりコストが低い、アニメの方が見てもらえるかもしれない

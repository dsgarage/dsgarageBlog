# Day2 S6「VRChatワールドができるまで」Skill 化用ノート

出典: Blender Fes 2026 AW Day2「VRChatワールドができるまで BlenderとUnityをつなぐ空間制作の基本ワークフロー」（Fujito、2026-09-27 16:15–17:15）。
凡例: 【話者】= 講演者の意見・運用上の判断、【事実】= Blender / Unity / VRChat の一般的な仕様、【画面】= 配信画面で確認した値。聞き取りが不確かなものは「(要確認)」。講演で扱われなかった項目は「(講演外)」と明記し、一般的な仕様の補足に留める。

## 前提・環境

- 【画面】Blender はステータスバー表示から 5.2.1 と見られる(要確認)。Unity は 2022.3.22f1、Windows 環境
- 【話者】Unity は VRChat が対応するバージョンを使う。講演時点では 2022.3.22f1 を Unity Hub からインストール
- 【事実】VRChat の対応 Unity バージョンは SDK の更新で変わるため、制作開始時に VRChat の公式ドキュメントで確認する(講演外)
- 【話者】プロジェクトは VRChat Creator Companion(VCC)で作る。ほかの方法もあるが基本は VCC から
- 【画面】VCC の New Project で「Unity 2022 World Project」を選び、Project Name と Project Location を入れて Create Project
- 【話者】VCC のプロジェクト画面で SDK のバージョン管理と追加パッケージ(動画プレイヤーなど)の導入ができる。最後に Open Project
- 【話者】ワールドのアップロードには VRChat アカウントが New User 以上のトラストランクである必要がある

## 1. 空間設計(考えるフェーズ)

- 【話者】工程は「考える」と「つくる」の 2 フェーズ。考えるフェーズは キーワード → ラフスケッチ → リファレンス の 3 段階
- 【画面】キーワードの項目: 年代・時間・季節・天気・場所・建築・雰囲気。今回は 現代 / 13:00 くらい / 夏 / 晴れ / 湖や森の近く / 別荘 / シンプル・隠れ家
- 【画面】制約条件も同時に書く: 広すぎない / 周辺は作りこまない / 夜景にも対応できる
- 【話者】「何を作りたいか」と与条件を先に明確にする(スライド表記は「与条件」、文字起こしの「余条件」は誤変換)
- 【話者】ラフスケッチは絵の上手さではなく、頭の中を図にして整理するためのもの
- 【画面】バブルダイアグラム: Pool / Living / Garden / Approach を円で描き、つながりを矢印で示す
- 【画面】平面スケッチ: Living 中心にスクリーン・キッチン、両側に Pool side と Garden、下に Approach と Lightwell(吹き抜け)、Spawn 位置も記入
- 【話者】平面では「歩いたときに何がどの順で目に入るか」を検討する(アプローチの吹き抜けの光 → 右手のガーデン → 奥のプール)
- 【話者】リファレンス収集は Pinterest。整理は PureRef、共同制作では Miro。特徴やエリアでグルーピングし、メモを付ける
- 【話者】作るものが多いときは Notion でリスト化し、プロップやギミック、全体の工数をあぶり出す
- 【話者】リファレンスはそのまま再現せず「構造化」する。要素を読み取り、自分の空間に当てはめて調整する(建築設計の検討手法の 1 つ)
- 【画面】断面スケッチ: Living FL±0 → Poolside FL-900 → Pool と段を下げ、庇と日差しの入り方を検討している

## 2. Blender でのモデリング(スケール・単位)

### ラフモデル
- 【話者】編集モードのオーバーレイで「辺の長さ(Edge Length)」を有効にし、スケッチの寸法と照合しながら作る
- 【話者】N パネルのトランスフォームを見ながら、きりのよい寸法で作る。建築は基本的にきれいな寸法で管理されている
- 【話者】人型モデルを置いて身体スケールで確かめる。VR では最終的に人が中に入るので特に重要
- 【画面】人型モデルの Dimensions Z は 1.6 m 前後(オブジェクト名は person_model_1500、要確認)
- 【話者】オーバーレイの「面の向き(Face Orientation)」を有効にし、赤(裏面)があれば反転(Flip)して表にする
- 【話者】裏向きの面は Unity に持ち込むと見えなくなることがある
- 【話者】粗い段階から徐々に細かくし、VR で体験しながら進める。今回はスケール確認後にこぢんまりした空間を付け足した

### 詳細モデル
- 【話者】ラフとの違いはテクスチャー設定と建築ディテールの追加
- 【話者】テクスチャーは CC0 素材。ambientCG や Poly Haven から選ぶ
- 【事実】Node Wrangler の Ctrl+Shift+T(Principled テクスチャーセットアップ)で、選んだ画像一式を Principled BSDF にまとめて接続できる
- 【話者】建築の収まりで実在感を出す例:
  - キッチン上部の間接照明用の折り上げ、窓上の空調吹き出し口
  - 床タイルの厚み(小口)を横から見えるように作る
  - モザイクタイルの目地を壁と床でそろえ、埋め込み照明も割り付けに合わせる
  - ガラスはフレーム + シール材 + ガラス。ドアには枠
  - キッチン天板に大理石の厚み、下の扉に手掛けの隙間
- 【話者】目的はフォトリアルではなく、VR 空間に入ったときの実在感

## 3. ポリゴン予算とメッシュの最適化

- 【話者】ソファー裏などで面がほぼ同じ位置に重なると Z ファイティング(表示のちらつき)が起こる
- 【話者】完成したワールドで絶対に見えない面、重なった面はできるだけ消す。描画負荷とデータ容量を軽くするため
- 【話者】不要な面はライトベイク時の容量増加の原因にもなる。Unity に持っていく前に Blender で整理する
- 【話者】コライダーは最終的に分割したり軽い形状にしたりと最適化を考えることがある(具体手順は未説明)
- 【事実】ポリゴン数の具体的な上限・予算値は講演で示されなかった(講演外)。VRChat 公式のパフォーマンスガイドで対象プラットフォームごとに確認する

## 4. UV とライトマップ

- 【話者】UV は「モデルのどこに画像のどこを貼るか」を決める座標
- 【話者】建築は直方体に近い形が多いので立方体投影(Cube Projection)で展開
- 【話者】UV は素材の実寸を基準にする。磁器質タイル 500 角(500×500mm)なら、シーン上 1m にタイルが 2 枚入るよう合わせる
- 【画面】UV Editing で granite_tile 系テクスチャー(2K)を使用
- 【話者】ライトマップ用 UV は Unity の Generate Lightmap UVs で自動生成できる(テクスチャー用 UV とは別)
- 【話者】サンプル数を上げても黒ずみが出る場合は、ライトマップ用 UV(UV2)を Blender で展開する必要がある
- 【事実】Blender で 2 つめの UV マップを追加して展開し、Unity 側で Generate Lightmap UVs をオフにすると、その UV2 がライトマップに使われる(講演外の補足、要確認)

## 5. FBX 書き出し設定

- ファイル > エクスポート > FBX
- 【話者】Limit to「選択したオブジェクト(Selected Objects)」にチェック。事前に Blender で必要なものを選択
- 【話者】オブジェクトタイプは Mesh のみ
- 【話者】パスモード(Path Mode)は「コピー(Copy)」。使用テクスチャーも書き出し先にコピーされる
- 【話者】右隣の「テクスチャーを埋め込む」ボタンはオフ。テクスチャーを別ファイルで管理するため
- 【話者】トランスフォーム: スケールを適用(Apply Scalings)=「FBX すべて(FBX All)」、前方(Forward)= -Z、上(Up)= Y
- 【話者】ジオメトリ: 「モディファイアーを適用(Apply Modifiers)」オン
- 【話者】保存先は Unity プロジェクトの Assets 内のメッシュ用フォルダー。Unity が変更を自動検知してインポートする
- 【話者】以降は Blender で修正して同じ FBX を上書きするだけで更新できる
- 【画面】フォルダー構成例: Assets/02_model(mesh)/00_Rough、01_model、03_texture、04_material など

## 6. Unity 取り込み(VRChat SDK)

### FBX のインポート設定
- 【話者】Materials タブで Extract Materials → Unity 側で編集可能なマテリアルとして取り出す
- 【話者】Model タブの Generate Lightmap UVs にチェック → Apply
- 【話者】ラフモデル取り込み時に Fix Now を押している(ノーマルマップ指定の警告と推定、要確認)
- 【話者】シーンに配置し、Transform の Position が 0,0,0 であることを確認

### マテリアル・シェーダー・テクスチャー
- 【話者】マテリアル = シェーダーの設定を持つもの。シェーダー = 描画の計算方法。テクスチャー = シェーダーに当てはめる画像データ
- 【話者】シェーダーは Autodesk Interactive(Unity 標準)。Standard にはラフネスマップを直接入れる枠がないため、Blender のラフネス運用を持ち込みやすいこちらを選ぶ
- 【話者】VRChat 向けのシェーダーもあるが今回は扱わない
- 【話者】ラフネスマップは数値データなので sRGB (Color Texture) のチェックを外す
- 【話者】ノーマルマップは Texture Type を Normal map にする
- 【画面】スライド注記: Normal GL と DX の違いに注意。凹凸が逆に見えるときは Flip Green Channel にチェック
- 【話者】マテリアルを全選択してシェーダーを一括変更。Project の検索欄に「rough」と入れてラフネスマップを全選択し、sRGB を一括で外して Apply
- 【話者】Rendering Mode はガラスと不透明物で異なるので個別に設定

### コライダー
- 【話者】まず Add Component で Mesh Collider を一括追加
- 【話者】公開前に、通り抜けたい扉と水面の Mesh Collider を外す

### Static とプローブ
- 【話者】Inspector 右上の Static にチェックしてライトベイク対象にする。項目ごとに用途は違うが、まずは完成優先で一括
- 【話者】Reflection Probe: マテリアルの映り込み用。最初は部屋ごとに 1 つ、周囲の見え方が大きく変わる場所ごとに置く
- 【話者】Reflection Probe の範囲は編集ボタンで部屋の境界に合わせ、Box Projection にチェック
- 【話者】Light Probe Group: 場所ごとの明るさを記録。ワールドを動き回るアバターのライティングに効く
- 【話者】Light Probe は初心者のうちは等間隔にざっくり配置でよい。Edit 状態で黄色い球を選び Ctrl+D で複製

### ライトベイク
- 【話者】全部の光をリアルタイム計算すると負荷が大きい。動かない建物は光と影をライトマップに焼き込むのが一般的
- 【話者】Directional Light(太陽)の Rotation で影の向きを決め、Intensity で強さを調整(基準値は聞き取れず、要確認)
- 【話者】Lighting ウィンドウで Environment Lighting(空や周囲から回り込む光)を設定し、Generate Lighting
- 【話者】ラフ段階のベイクは完成照明が目的ではなく、VRChat 内でスケール感と雰囲気を確かめるため
- 【話者】本番も最初は低サンプルで試し、間接照明のライト・日の入り方・室内の明るさを確認してから、最後にサンプル数を上げる
- 【話者】ベイク時にラフネスマップの設定漏れもチェックする
- 【画面】16:53 時点の Lighting 設定: Baked Global Illumination オン、Lighting Mode = Subtractive、Lightmapper = Progressive GPU (Preview)、Direct Samples 1 / Indirect 8 / Environment 8、Max Bounces 4、Denoiser = Optix、Filter = Gaussian、Lightmap Resolution 40、Padding 2、Max Lightmap Size 4096、Compression High Quality、Ambient Occlusion オン、Directional Mode = Directional(低サンプルの試し焼き段階の値)
- 【話者】植物は Unity Asset Store の無料アセットを使用

### オクルージョン
- 【事実】オクルージョンカリング(Occlusion Culling)は講演では扱われなかった(講演外)。遮られて見えない物体の描画を省く Unity の機能で、VRChat ワールドの最適化で一般的に使われる
- 【画面】Autodesk Interactive のマテリアルに Occlusion(アンビエントオクルージョンのマップ)枠があるが、講演では使用していない

### Post Processing(PC 向けのみ)
- 【話者】VRChat の Post Processing は Windows 向けワールドでは有効、Quest / Android / iOS 向けでは無効
- 空のゲームオブジェクトを作り、名前を付ける(例: PostProcess)
- Add Component → Post-process Volume → Is Global にチェック
- Layer → Add Layer で Post Processing 用のレイヤーを作る(講演では 22 番)→ Volume のオブジェクトをそのレイヤーに
- Main Camera に Post-process Layer を追加し、Layer にさきほどのレイヤーを指定
- Volume でプロファイルを新規作成し、エフェクトを追加
- Bloom: 明るい部分をにじませる。Intensity を少し上げる。強すぎると眩しくぼやける。Threshold でかけ始める明るさを決める
- Color Grading: トーンマッパーを設定(聞き取りは「ASUS」、ACES と推定・要確認)、Post-exposure を少し上げ、Saturation と Contrast をわずかに調整
- 【話者】色調整に正解の数値はない。ワールドの雰囲気を見ながら決める

### スポーンとビルド
- 【話者】VRCWorld オブジェクトの位置がスポーン(最初にアバターが立つ場所)。平面スケッチどおりアプローチ空間に置いた
- 【話者】シーンビューのギズモ表示切り替えで記号を消すと作業しやすい(ボタン名は要確認)
- 【話者】VRChat SDK > Show Control Panel。ワールド名・キャパシティ・説明・サムネイルの設定欄、警告パネル、ビルドパネルがある
- 【話者】サムネイルは Capture in Scene でシーンから撮るか、Select Image で画像を選ぶ
- 【話者】警告は Auto Fix で解消できる
- 【話者】試すだけなら Build & Test Your World、公開は Build and Publish Your World Online。Publish は確認のチェックボックスを入れないと押せない
- 【話者】アップロード失敗時は Console に理由が出る

## 7. 最適化と検証

- 【話者】ラフモデルの段階から Build & Test で VRChat に入って確かめることが、良いワールドを作るポイント
- 【話者】HMD があれば Blender の VR Scene Inspection アドオンで Unity 前に確認できる
- 【画面】VR Scene Inspection は 3D Viewport のサイドバー VR タブに Start VR Session などが並ぶ。Blender の VR は OpenXR ベース
- 【話者】公開後は VRChat の Web サイトでワールド情報(容量など)を確認できる
- 【画面】今回のワールド BlenderFes_Villa は 103.77 MB(軽量化をまだ行っていない状態)
- 【話者】容量は 100MB を超えないことを 1 つの基準にしている。Quest 対応や iOS 対応のときの基準になるため(文字起こしの「100Mbps」は MB の誤変換)
- 【話者】入室時にインスタンスタイプを選ぶ。Friends = フレンドが入れる、Invite = 招待した人のみ
- 【話者】デスクトップではマウスホイールで三人称視点に切り替えられる。Web カメラでのトラッキングも可能
- 【話者】最後に VR でも確認する

## 判断基準・落とし穴のまとめ

- 【話者】作り始める前に、キーワードと制約条件で与条件を決める。ここが曖昧だと空間が決まらない
- 【話者】リファレンスは再現しない。要素を抜き出して自分の空間に当てはめる
- 【話者】寸法はきりのよい値で、人型モデルで身体スケールを常に確かめる
- 【話者】裏面は Unity で消える。書き出し前に面の向きを確認
- 【話者】FBX は同じパスに上書きする運用にして、Blender → Unity の往復を軽くする
- 【話者】UV は素材の実寸基準で合わせる。スケールがずれると建築らしさが崩れる
- 【話者】見えない面・重なった面は Blender で消してから持ち込む(Z ファイティングとベイク容量の両方に効く)
- 【話者】ラフネスマップの sRGB オフ、ノーマルマップの Normal map 指定を忘れない。凹凸が逆なら Flip Green Channel
- 【話者】ライトベイクは低サンプルで何度も試し、最後に上げる。黒ずみが消えないなら UV2 を用意
- 【話者】Mesh Collider の一括付与は仮。扉や水面など通り抜けたい所は外す
- 【話者】Post Processing は PC 版でしか効かない。Quest / iOS 向けの見た目を後処理に頼らない
- 【話者】容量は 100MB 以内を目安にする。マルチプラットフォーム対応を見据えるなら早めに意識する
- 【話者】早い段階から VRChat の中で体験して判断する

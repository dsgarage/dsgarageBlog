# S6「エフェクトを作ろう」Skill 化用ノート

出典: Blender Fes 2026 AW Day1「エフェクトを作ろう」（牛乳瓶、2026-09-26 16:15–17:15）。
凡例: 【話者】= 講演者の意見・運用上の判断、【事実】= Blender の一般的な仕様、【画面】= 配信画面で確認した値。聞き取りが不確かなものは「(要確認)」。

## 前提・環境

- 【話者】使用アドオンは Node Wrangler と Mio3 UV。デモの操作を再現するなら事前に有効化しておく
- 【画面】デモのレンダーエンジンは EEVEE（プロパティパネルで確認）。Blender のバージョンは 5.x 系と見られる(要確認)
- 【事実】Node Wrangler の Ctrl+T: テクスチャノードを選んで押すと、テクスチャ座標とマッピングが自動で追加・接続される。既定は Generated 出力なので、UV を使うときは UV 出力につなぎ直す
- 【事実】Node Wrangler の Ctrl+0（テンキー）: 2 つのノードを選んで押すと Mix でマージされる。カラー出力ならミックスノード、シェーダー同士ならシェーダーミックスになる(キー割り当ては要確認)

## 基本原理: テクスチャを「動かす」2 つの方法

- 【事実】ノイズ／ボロノイの次元を 4D にすると入力 W が増える。W を動かすと、模様が移動せずに形そのものが変化する
- 【事実】マッピングノードの位置(Location)を動かすと、模様の形は保ったまま座標がずれて「流れる」
- 【事実】入力欄にドライバー式 `#frame/N` を入れるとフレームに比例して値が増える。N が大きいほど遅く、N を負にすると向きが逆になる
- 【話者】動かすのはモデルではなくテクスチャ座標、という捉え方が出発点
- 【話者】流す動き(座標の加減算)と形を変える動き(W)は別々に速度調整できる。速く流したいが形は変えたくないなら、流す側の分母を小さく、W 側の分母を大きくする
- 【話者】動きが落ち着かないときは、片方ずつドライバーを外して値を固定し、どちらの動きが強すぎるか切り分ける
- 【話者】値ノードのあとに乗算を挟んでおくと、速度の微調整が 1 か所で済む

## 作例 1: ブラックホール風の渦（マテリアル＋メッシュ変形）

### メッシュと UV
- 円を追加 → 面を張る → 中央に穴を開ける(内側の円を縮小)→ シームをマーク → ループカットを数本入れる
- UV 展開後、Mio3 UV でグリッド化・正規化して UV を整列させる(機能名は要確認)
- 【話者】初期状態では外周と中心が左右に並ぶので、UV を 90 度回転し「下端＝外周、上端＝中心」にそろえる。これで円を帯として扱え、UV の Y が「外周→中心」の距離になる

### 流れる筋
- ボロノイテクスチャ → Ctrl+T → テクスチャ座標は UV
- マッピング: スケール Y 0.3、ボロノイ: スケール 23(聞き取りでは「マッピングの Y を 0.3」、画面ではボロノイのスケール 23.000 を確認)
- カラーランプ: 補間を B-スプライン、黒の位置を詰めて筋状にする
- マッピング位置 Y にドライバー `#frame/-70` → 中心へ流れる(講演中の「170 分の 1」は「70 分の 1」の誤変換と判断)

### 粒子(きらめき)
- 上の 4 ノード(座標・マッピング・ボロノイ・カラーランプ)を Shift+D で複製
- 【画面】マッピング: スケール X 2.0 / Y 0.7、ボロノイ: 3D・F1・距離関数ミンコフスキー、スケール 23、指数 0.5、ランダムさ 1.0
- 【事実】ボロノイの距離関数をミンコフスキーにして指数を 1 未満にすると、セルが星形(四芒星状)になる
- カラーランプの白黒を反転し、スケールを少し小さくする
- ドライバー `#frame/-100`: 筋(-70)と速度をずらして重ねる
- 2 つのカラーランプを Ctrl+0 でミックス。ブレンドモードは「比較(明)」系を選んだと見られる(聞き取りは「軽い方」、要確認)

### マスクと発光
- テクスチャ座標(UV)→ XYZ 分離 → Y をカラーランプへ → 外周に向けて暗くなるマスク
- マスクを数式ノード(乗算)で模様に掛ける。カラーランプを B-スプラインにして端を黒く寄せる
- 同じカラーランプを複製し、中心が明るくなるマスクを作る → ミックスの係数に接続、A に乗算結果、B を白 → 中心だけ白く飛ぶ
- 放射(Emission)と透過 BSDF を Ctrl+0 でシェーダーミックス、係数に上のミックス結果 → 明るい所だけ光り、暗い所は透明
- ミックス結果に乗算を挟んで放射の強さへ → 乗算値で明るさ、放射カラーで色を決める
- 【話者】外周マスクの目的は模様の演出ではなく、メッシュの端を見せないこと。係数を無視すると円の外縁まで見えてしまう

### ねじれ(渦)
- 編集モードでループカットしたメッシュの外側を選択 → プロポーショナル編集を有効化 → R Z で回転し、影響範囲を調整
- 【話者】ねじれはシェーダーでも作れるが、メッシュ変形のほうが手早い。「形で調整しやすいところは形で調整する」

### 調整の観点
- 【話者】完成後に各ノードを単独表示して役割を確認する。細かい模様は流れの細部、大きな模様は全体の明暗変化を担う
- 【話者】2 つのマッピングを同じ速度にすると重なり方が単調になる。差をつけるときは 1 つずつ変えて効き方を見る
- 【話者】ドライバーの符号を反転すると「吸い込み」と「放出」を切り替えられる
- 【話者】新しいノードを足さなくても、模様の組み合わせ・速度・見せる範囲・流れる向きの 4 点で印象を変えられる

## 作例 2: 光が流れる模様（明るさと色を別枝で）

### 明るさの枝(白黒で先に作る)
- UV 展開した平面 → ノイズテクスチャ → Ctrl+T → テクスチャ座標の UV をマッピングのベクトルにつなぎ直す(マッピングは初期値)
- マッピングとノイズのあいだに XYZ 分離を入れ、X だけをノイズに渡す
- ノイズ: 4D、スケール 10、細かさ(Detail)2、粗さ(Roughness)0.5(既定のまま)
- 【画面】16:49 のノード画面: ノイズは 4D・fBM・正規化オン・空隙性(Lacunarity)2.0・歪み 0。XYZ 分離 → ノイズ → 減算(Y を引く)→ 減算(値ノード)→ 小数部の順につながっている
- 【事実】X だけを渡すと、同じ X では上下どこでも同じ値になり「縦に伸びた」模様になる。Y だけなら横に伸びる。分離せず渡すと通常のノイズ
- 【話者】筋状の模様が欲しいとき、ノイズを引き伸ばす以外に「座標の一方向だけを渡す」方法がある
- 数式「減算」: 上にノイズの係数、下に UV の Y → 高さで明るさが変わり、その境界がノイズで凸凹になる
- 【話者】ノイズは色として使うだけでなく、グラデーションの形を崩す道具になる
- 数式「小数部(Fraction)」を後ろにつなぐ
- 【事実】小数部は 1.2→0.2、2.2→0.2、-0.2→0.8 を返す。値が 0〜1 の範囲を繰り返すので明暗の縞が繰り返される。減算で負になった部分も 0 以上 1 未満に収まる
- 【事実】Y に乗算で 3 を掛けてから小数部を通すと、グラデーションが 3 回並ぶ。小数部の手前で値を足し引きすると繰り返しの位置がずれる
- 小数部の直前に「減算」をもう 1 つ入れ、下の入力に値ノード(ドライバー `#frame/100`)→ 模様が流れる
- ノイズの W にドライバー `#frame/1000`(聞き取りは「分の線」、1000 と推定・要確認)→ 凸凹の形もゆっくり変わる
- 小数部の後ろに数式「累乗(Power)」指数 1.5 → 0〜1 の値では中間が暗くなりメリハリが出る(0.5 の 2 乗が 0.25 になるのと同じ理屈)
- 結果を放射の強さへ

### 色の枝
- 波テクスチャ(Wave Texture)→ Ctrl+T → UV 接続、マッピングは初期値
- 種類: リング(Rings)、方向: Y(聞き取りどおり。要確認)、プロファイル: サイン、スケール 0.12、歪み 0
- 【話者】細かい縞ではなく、ゆったりした色の変化を作るために使う
- 波テクスチャのカラー → カラーランプの係数 → 好みの色を配置
- 位相オフセット(Phase Offset)に値ノード(ドライバー `#frame/30`)→ 色が時間で変化
- カラーランプ出力を放射のカラーへ

### 進め方
- 【話者】「模様の形 → 動かし方 → どこを明るくするか → 何色にするか」を分けて考える
- 【話者】白黒で模様を確認 → 動かす → 明るさを整える → 色、の順にすると、思いどおりにならなかったときにどの段階で差が出たか特定できる
- 【話者】完成形のノードが最初から頭にあるわけではなく、途中結果を見ながら計算や色を足していく

## 作例 3: 糸がほどけるトランジション（ジオメトリノード＋マテリアル）

### キャラクターの出現マスク
- テクスチャ座標のオブジェクト出力 → XYZ 分離で Z を取り出す → 値の足し引きで上から下へ動く白黒マスク
- ミュートしていた 2 ノード(ノイズ系と推定・要確認)を有効化すると境界が歪む。歪み具合はミックスの係数で調整
- この白黒をマスクにしてキャラクターのトランジションを作る

### パスに沿って光を走らせる
- カーブのパスを置き、ジオメトリデータの押し出し(Extrude)で幅をつける
- 【事実】カーブをメッシュに変換すると、端から端に対応した UV が自動で作られる
- 【話者】パスの長さが違っても、この端から端の座標を同じように使えるのが利点
- UV → グラデーションテクスチャ(黒→白が端から端へ)→ 数式「加算」で位置をずらす → カラーランプ → 黒い部分をアルファ(透過)へ、係数の一部を色用カラーランプへ

### 値をモディファイアーからマテリアルへ渡す
- 【話者】マテリアルを複製してパスごとにタイミングを変えると、後で色を変えるときに全部直すことになる。共有したまま値だけ個別に渡す
- ジオメトリノード: 「名前付き属性を格納(Store Named Attribute)」で属性を作る(講演では属性名「point」と聞こえた、要確認)
- 格納ノードの値にグループ入力をつなぎ、入力を公開 → モディファイアーパネルから数値を設定できる
- マテリアル: 属性(Attribute)ノードで同じ名前を指定 → 取り出した値を位置をずらす加算ノードへ
- 【事実】パスが別オブジェクトなら、同じジオメトリノードグループ・同じマテリアルを使いながら、モディファイアーの値はオブジェクトごとに持てる
- モディファイアーの値にキーフレームを打つ → 光がパスに沿って進む。開始フレームを少しずつずらすと順にほどける流れになる
- 【話者】等間隔にこだわらず、同時に動かす・少し遅らせるなど映像を見ながら調整する。MV なら音のタイミングに合わせる
- 【話者】色や光の幅など全体でそろえたいものは共通マテリアル、位置やタイミングなど個別に変えたいものはモディファイアー。パスが増えても調整しやすい
- 【話者】ジオメトリノードは形を作るだけでなく、マテリアルを操作する窓口として使える。後から触りそうな値を触りやすい場所に出しておく

## 組み合わせ演出の構成(紹介のみ、手順の詳細なし)

- 魔法陣: 画像素材に出現アニメーションをつける。「これから何かが起こる」入り口を作る
- 煙・パーティクル: シミュレーションを使用(具体的な手法は未説明)
- 煙がぶつかるタイミングでオブジェクトが変化: アドオン「Animax」を使用(表記要確認)
- 上から下へ光が移動するマテリアルを重ね、変化の瞬間を強調。変化に合わせてパーティクルも発生させる
- 空間に浮かぶ小さな光、杖の先端の発光、窓から差し込む光(ボリューム)で雰囲気を補う
- 【話者】コンポジットで光のにじみや色を調整する前提で素材を分けておくと、映像全体になじませやすい

## 判断基準・落とし穴のまとめ

- 【話者】ノードの並びや数値を暗記しない。「座標から模様を作る → 値を動かす → 見せ方を調整する」の型で考える
- 【話者】全部を 1 つの手段で作ろうとしない。形で直せるところはメッシュ、模様はシェーダー、個別制御はジオメトリノードに分担させる
- 【事実】Node Wrangler の Ctrl+T は Generated 座標で接続されるため、UV 前提のエフェクトではつなぎ直しを忘れると模様がずれる
- 【話者】放射だけにするとメッシュの端が見えてしまう。透過とのミックス＋外周マスクで端を消す
- 【話者】共有マテリアルに直接キーを打つと全オブジェクトが同じ動きになる。個別タイミングはモディファイアー経由の属性で渡す
- 【話者】まずはノイズの値を動かすところから始め、細長くする・円に乗せる・光る所だけ取り出す、と試して広げる

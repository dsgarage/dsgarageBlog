# S2 スキル化メモ: イラスト調キャラクターシェーディング（Blender / Goo Engine）

出典: Blender Fes 2026 AW Day1 S2（三縁エイト、MC 藤田将）。凡例は次のとおり。

- 【話者】登壇者の方針・意見・経験則
- 【MC】進行役の補足・意見
- 【事実】Blender / Goo Engine の機能としての一般的事実（スライド表記や Blender マニュアルで確認できたもの）
- (要確認) 聞き取りが不明確、または機能名・挙動を未検証のもの

## A. ワークフロー設計の判断基準

1. 【話者】作業追加は「1カットの手間 × カット数」で見積もる。1カット10分の追加は200カットで2000分（約33時間）になる。追加作業を入れる前に掛け算で判断する
2. 【話者】最初に目指すのは「安定して80%を全カットで出す仕組み」。100%を目指すレタッチ前提の少数カット制作は後回しにする
3. 【話者】レタッチや1カットごとの修正を減らし、仕組み単体で完成形に近い絵を出す。これが完成と品質の両面で効く
4. 【MC】全カットを100%にすると、それが基準線になり差が出ない。見せ場のカットだけ出し切り、ほかは80%に抑える配分を設計段階で決める
5. 【話者】「感覚でやっていたことをシステムで再現する」。絵を描くときの無意識の判断を抽出し、「どの条件で・何をしているか」に分解してから、シェーダーノード/ジオメトリーノードに置き換える
6. 【話者】シェーダーを組む前に、目標のルックをデザイン画として描いておく
7. 【話者】個人・少人数でセルルック3DCGを選ぶと、カットごとの2D的調整（リグ・レタッチ）が必要になり、手数で勝る商業作品の劣化版になりやすい。人数と手数に合う土俵を選ぶ
8. 【話者】3DCGは「テクスチャと造形の一貫性で存在を保証する」媒体なので、線（輪郭の揺れ）より塗りで勝負する方が向く、という見立て
9. 【話者】アニメ調ゲームのリアルタイムシェーダー（リムライト、フェイスシェーディング等）を参照すると、どの角度でも破綻しない自動化の仕組みを流用できる
10. 【話者】パラメータを入れすぎない。顔の SDF 各種パラメータは結局一部のカットでしか使わなかった。初回は必要最小限にし、足りなければ足す
11. 【話者】リムライトの色はシェーダー内で決め打ちせず、左右のマスクを別出力して After Effects で色付けすると、シーンごとの色替え・片側だけ消す・強めるが後から効く

## B. Goo Engine（Blender カスタムビルド）

12. 【事実】Goo Engine は DillonGoo Studios が開発した NPR 向け Blender カスタムビルド。有料で Patreon から入手（価格は話者談で約5ドル、要確認）。『砂塵ノ中デ』は Goo Engine 4.1 を全編使用
13. 【事実】以下のノード/機能は標準 Blender には無い（少なくとも Blender 4.1 時点。最新の本家への取り込み状況は要確認）。スキル化する際は「Goo Engine 必須」と明記する
14. 【事実】Shader Info ノード: 出力 Diffuse Shading / Cast Shadows / Self Shadows / Ambient Lighting、入力 WorldPosition / Normal、Light Groups チェックボックス。N パネルでライトグループを指定すると、そのグループのライトだけの結果を返す
15. 【事実】Curvature ノード: 出力 Scene Curvature / Scene Rim、入力 Samples / Sample Radius / Thickness（または「幅」）/ Scale。Scene Rim はスクリーンスペースでシーンをサンプリングしシルエット付近を検出する
16. 【事実】Screenspace Info ノード: 出力 Scene Color / Scene Depth、入力 View Position。画面上の色・深度をマテリアル内で取得できる
17. 【事実】Set Depth ノード: シェーダーと View Depth を受け取り、マテリアル側で描画順（深度）を操作する
18. 【事実】ライトのプロパティにライトグループ設定があり、「Use Default Group」（既定グループへの登録）を外すと、そのライトはグループ指定したマテリアルにしか効かなくなる（表記要確認: スライド上は「Use Default Gr...」「Ignore Default...」が見える）

## C. Fresnel と Scene Rim の使い分け

19. 【事実/話者】Fresnel をリムライトのマスクに使うと、内側にもマスクが入り込み、メッシュ形状依存で線幅が変わる（浅い面が続く頭頂は太く、急なエッジの耳の端は細い）。均一な輪郭リムには不向き
20. 【事実/話者】Scene Rim はスクリーンスペース基準なので輪郭線に近い均一なマスクになる。リムライトの輪郭強調に使う
21. 【話者】Scene Curvature（凸部の検出）は動くオブジェクトに使うとちらつきやすい。開発元は静止した背景物（ポストなど）に使っている例がある
22. 【話者】Scene Curvature の結果を Map Range でマイナス側に振ると、凹部に影を乗せる AO 風の表現になる（要確認: 具体的な Map Range の値は未提示）
23. 【MC】標準 Blender で近いことをするなら Ambient Occlusion ノードの Inside オプションで曲率風の値が取れるが、形状とサンプリングに依存する

## D. リムライトの組み方（デモ手順）

24. 準備: アーマチュアで簡易リグを入れたメッシュ、サンライト1灯、カメラ。部位の基準点としてボーンに拘束したエンプティを用意（デモでは2本目のボーンに Child Of 等で追従、拘束の種類は要確認）
25. サンライトを複製してリムライトにし、カメラにコンストレイントして常にカメラの左側から当たるようにする（拘束の種類は要確認。Child Of か Copy Rotation 系と推定）
26. リムライトに専用ライトグループ（例: Rim01）を作り、Use Default Group を外す。メインのサンライトにも別グループを付ける
27. マテリアルに Shader Info を置き、ライトグループを指定。メイン光とリム光を別々の Shader Info で取り出す
28. 通常ライティングの明暗はライト強度ではなく、マテリアル内の Color Ramp で調整する（Shader to RGB が不要になる）。リム光の強度はデモでは 10 程度に上げた
29. 通常の陰影は Diffuse Shading × Cast Shadows（乗算）で得る。落ち影だけ欲しいときは Cast Shadows を単独で使う
30. Curvature の Scene Rim を Color Ramp で絞り、リム光の結果に Add で足して輪郭をくっきりさせる。ライトの色は消し、色はマテリアル内の Mix で付ける（本番では AE で付ける）
31. 左右マスク（ジオメトリーノード側）: Object Info でエンプティの Location を取り、Position との差（Position − Location）を Store Named Attribute で属性に保存。このモディファイアはアーマチュアモディファイアの後に置き、変形後の位置に追従させる
32. 左右マスク（シェーダー側）: Attribute ノードで属性を読み、Vector Transform（Camera → World）でベクトル (1, 0, 0) を変換してカメラの横方向を得る。両者の Dot Product → Color Ramp で 0/1 化 → Mix（乗算）でリムの片側を消す。符号を間違えると反対側のマスクになる（デモでも -1 → 1 に修正）
33. Texture Coordinate / Position をそのまま使うと、原点基準・メッシュ依存のグラデーションになり、縦長の人型では部位ごとにずれる。顔・髪・背骨など部位ごとの基準点は、ジオメトリーノードから属性で渡す
34. 柔らかいリムを重ねたい場合は、Scene Rim を別の Color Ramp でぼかして同じ片側マスクに掛け、足す
35. 反対側のリム: ライトを複製し新しいライトグループを作り、回転を逆向きにして別色（デモでは青）にする。Shader Info とベクトル符号以外をノードグループ化して左右で共有すると一括調整できる
36. マスクの効き具合（グラデーション幅）は Color Ramp で調整。値をジオメトリーノード側のモディファイア入力に出せば、カットごとの調整窓口にできる

## E. アクティブカメラに追従するリムライト

37. 問題: 特定カメラにライトを拘束すると、カメラを切り替えたカットで追従しない。200カットで付け直すのは非現実的
38. 【事実】ジオメトリーノードの Active Camera ノードは、シーンの現在のアクティブカメラを出力する（Blender マニュアル: modeling/geometry_nodes/input/scene/active_camera）。導入バージョンは話者談で 4.1 前後（要確認）。ジオメトリーノード専用でコンストレイントからは直接参照できない
39. 手順1: 1頂点のメッシュを作り、X 方向に 1 押し出して2頂点の棒（エッジ）にする。頂点は回転を持たないため、向きを得るには2点が必要
40. 手順2: 棒の根元の頂点に頂点グループ1、先端に頂点グループ2を割り当てる
41. 手順3: 棒にジオメトリーノード: Active Camera → Object Info（Location / Rotation）→ Transform Geometry に接続し、棒をアクティブカメラの位置・向きに移動させる
42. 手順4: エンプティに位置のコンストレイント（ターゲット=棒、頂点グループ1）と Track To 系のコンストレイント（ターゲット=棒、頂点グループ2、Track Axis = X）を付ける（位置側の拘束の種類は要確認。Copy Location と推定）
43. 手順5: リムライトの拘束先をカメラからこのエンプティに変更し、ずれた分はライト側の回転で補正する。以後、アクティブカメラを切り替えてもリムライトが追従する

## F. フェイスシェーディング（SDF）

44. 【事実】SDF フェイスシェーディング: 光の向きに応じて影境界が移動する距離場テクスチャを使い、法線に頼らず顔の陰を制御する一般的手法
45. 【話者】よく使われる「頬に三角形の影が乗る」タイプの SDF は、遷移の途中で不自然な形状が出る
46. 【話者】純粋なグラデーションの SDF は遷移がきれいだが、顔のアップでは情報量が足りない
47. 【話者】解決策: 基本 SDF に加え、RGB 各チャンネルに別マスク（頬のハイライト、鼻のハイライト、鼻の影など）を持つ画像（例: T_head_shadow_mask）を用意し、個別に制御する。さらにブラーをかける
48. 【話者】SDF の閾値処理に Map Range を入れて遷移の幅（Gradation_range）を持たせると、影の柔らかさが大きく変わる
49. 【話者】顔のパラメータはジオメトリーノードのモディファイア（例: GEO_face_CTRL）の入力として公開し、シェーダー側は Attribute で受ける。画面上の項目例: Dirt_mask_01〜03, Cheek_light, Gradation_range, Mouth_shadow, Nose_light, Nose_shadow, Under_shadow, EyeSlash_trans（項目名は画面から読み取り、要確認）
50. 【話者】頬と、鼻から目の上にかかるライティングが3DCGキャラクターのシェーディングの鬼門
51. 【MC】鼻の影・ハイライトは顔表面の形状とは別次元で扱う必要があるため、白黒の SDF とカラー（RGB）マスクの併用が有効

## G. 髪の法線編集

52. 方式1 そのまま: 基準
53. 方式2 DataTransfer 適用: 球などの頂点法線を Data Transfer で転写し適用。変形に追従できずノイズが出やすい
54. 方式3 DataTransfer 保持: 複製したメッシュからトポロジーベースで転写し、モディファイアを残す。小さいノイズが出ず細かい法線編集ができるが、ライティングが張り付いて見え、大きく見るとノイズになることがある。変形の小さい顔に使う
55. 方式4 ジオメトリーノード法線: 位置情報（部位基準点）から滑らかな法線をジオメトリーノード内で動的に生成。アニメーションの変形の影響を受けず完全に滑らか。細かい法線編集はできない。変形の大きい髪に使う
56. 【MC】Blur Attribute ノードで法線や属性を強制的に滑らかにする手も有効
57. 【話者/MC】モディファイアでできることも、あえてジオメトリーノードで組むと、属性の取り出しや後からの編集・アイデアの追加がしやすい（どちらの発言かは要確認）
58. 【事実】顔オブジェクトのモディファイアスタック（12:19 の画面から読み取り）: GEO_FaceAttribute → Armature → Subdivision → DataTransfer → GEO_LVector → GEO_eyeTrans の順。部位基準の属性はアーマチュアより前にも置かれている点に注意（GEO_FaceAttribute の中身は未解説、要確認）

## H. そのほかの仕込み

59. 前髪の落ち影: 髪メッシュを複製して影用メッシュにし、Goo Engine の Screenspace Info で画面上の肌色を取得して乗算的に色を乗せる。パラメータはジオメトリーノードで制御。ゲームのキャラクターシェーダーでも使われる処理
60. 【MC】コンポジットで前髪の影をずらす方法は、カメラ距離が変わると顔全面が影になるなど調整が難しい。またコンポジットの結果はマテリアルに戻せない
61. 髪越しに透ける目・眉・まつ毛: 元オブジェクトとは別に、オブジェクトとマテリアルを複製した半透明版（Alpha Blend）を重ねる。Goo Engine の Set Depth ノードで描画順をマテリアル側から制御する
62. 【MC】標準 Blender（EEVEE）でブレンドモードを Dithered 以外にすると AOV が出せない問題がある（要確認: Blender バージョンにより異なる）。複製して通常版と半透明版を分ければ AOV の問題を回避できる、というのが話者の運用
63. 影境界の SSS 風の色: Shader Info の WorldPosition 入力をライト方向（話者も「だったかな」と曖昧、要確認）に少しずらした Shader Info と、ずらしていない Shader Info の差分を取り、その差分領域に彩度の高い色を乗せる。Goo Engine 必須
63-2. 影側の反射光: ライトの向きの根元と先端にエンプティを置き、ジオメトリーノード（例: GEO_LVector）で2点の位置を引き算してライトベクトルを属性化する（アクティブカメラ追従と同じ「2点で向きを得る」発想）。シェーダーでライトベクトルと法線の内積を取り、光の反対側に弱い色（作例では青）を乗せる。エンプティをライトにどう拘束しているかは未解説（要確認）
63-3. 【話者】こうした処理は「イラストの描き方を分解して再現する」ものの一例。3DCGらしさの先に行くことを目標に組む
63-4. 【MC】同じ仕組みでもパラメータ調整で柔らかくもくっきりにもでき、ノードの組み方に作家性が出る
64. 本番のライト構成例（画面の Outliner から）: キャラクターごとに LIT_<キャラ>_body / face / hair / Rim_L / Rim_R / shadow のようにライトを部位別に分割し、ライトグループで対応する部位にだけ効かせている（命名は画面から読み取り）

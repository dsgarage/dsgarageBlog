## 2. セットアップ手順

- 【話者】最大のハードルは Claude Code / Codex のインストール。慣れた人なら 15 分程度。入れた後は Blender のインストール・MCP 設定も AI に任せられる

- 【話者】posi_posi さんの初回依頼は「Blender をインストール → MCP 設定 → 何かモデルを作る → いい画像を撮る → 納品」まで 1 回で指示

## 3. MCP と CLI の使い分け

- 【画面】MCP は対話で少しずつ。長い処理・本番レンダーは CLI（`blender -b --python`）
- 【画面】MCP の同期呼び出しは 2〜3 分で切れる → 重い処理は MCP で投げない
- 【画面】レンダーは Cycles / EEVEE。検査用は低解像度でよい
- 【話者】どちらを使うか、レンダー解像度、寄り・引きのカメラも AI に判断させている（posi_posi）

## 4. プロンプトの型

- 【話者】長いプロンプトを 1 回で書くのではなく、短い指示＋自己改善ループで詰める
- 【画面】差は「上手い/下手」ではなく「決定の所在」。決めていない値は AI が最小コストで埋める
  - NG: 「マグカップを作って」→ 上面が塞がった円筒。取っ手はカメラの死角
  - OK: 「外径 82mm・肉厚 4mm・高台・D 字断面の取っ手・磁器」→ 中空・取っ手・高台が出た
- 【画面】結果が変わった指定の型: 寸法と単位／個数と間隔／材質名／光の色温度／カメラの高さと狙い。専門用語は圧縮された指示（「高台」「肉厚」の 1 語が寸法と構造を渡す）
- 【画面】2 段構え: まず自分が良し悪しを判定できる題材で気軽に丸投げ → 品質を上げたくなったら仕様書化。人には自明でも AI に自明でない条件（「中空」）を言語化できるかが分水嶺
- 【画面】専門機能は「指名」しないと使われない。AI は頼まれない限りプリミティブ＋単色マテリアルで済ませる。「Bevel を入れて」「Array で」と機能名で言う
- 【話者】ゴールを伝える: 背景にうっすら映るだけか、前景のアセットか、で必要な品質が違う
- 【話者】作る前に「なぜそこにその物があるか」を考えさせる（階段は一段ずつ踏むので抜けてはいけない、手すりは人が歩く高さ）と抜け漏れが減る
- 【話者】抽象的な部分や未確定の条件があればユーザーに質問するよう指示しておく（KOBATAKA）
- 【話者】記憶させたい観点・記憶させたくない観点を明示する。何でも記憶させると混ざって質が下がる（posi_posi）
- 【話者】無茶振りでもまず 1 回頼んでみる。人間側が「難しいだろう」と決めつけない
- 【話者】実例: エスプレッソマシンの最初の指示は「X でバズるような超かっこいいのを作って」だった（丸投げでも提案が返る）

## 5. ワークフロー（KOBATAKA 版）

1. 制作の目的を決める（人間）
2. 目的達成に必要な専門知識と手段を AI に Web 調査させる（「その分野のプロならどこを見るか」）
3. 作業の仕様を決める: 単位、固定する条件、変数にする部分
4. Blender で実行
5. AI 自身が検査: 画像で確認＋寸法・座標を数値で取得
6. 人間がチェック

- 【話者】人間側で手順が描けているなら 3 から始めてもよい。ただし建築では 1→2→3 の順が有効
- 【話者】作業中に AI が出した仮説・違和感を次のお題にして自分で検証させ、仕様書を AI 自身が上書きする運用を試行中

## 6. ワークフロー（posi_posi 版＝AI に解説させたもの）

- 【画面】人: 意図・寸法・専門用語・監査基準・最終判断 → AI エージェント → Blender（MCP / CLI）→ レンダー → AI が自分で見る（画像を読んで課題を列挙、数値ゲートで機械判定）→ ループ
- 【話者】専門用語・チェックポイント・プロの監査基準も最初に AI に検索させる（全自動）
- 【話者】AI が最初に決めた監査基準を満たせば納品、満たさなければ改善ループ。足りなければ参照画像の再生成や専門知識の追加調査
- 【画面】「今日の話の 8 割はループの右半分」。操作できるのは 1 年前から。変わったのはレンダーを自分で見て直す往復ができるようになったこと
- 【画面】「コードは読めるが、書かない」。bpy は読めるが作例で自分が書いた行は 0。読めることは監査で役立つ

## 7. 反復（イテレーション）の段階 — 木の例、11 ラウンド

- 【画面】① 一発生成: 「木を作って」だけでは球の塊
- 【画面】② AI の自己改善: AI が自分のレンダーを読んで再帰分岐を実装。ここまでは AI だけで進む
- 【話者】比較用の実物画像は画像生成（GPT の画像生成）で作り、自作レンダーと比べて「本当に同じものか」と問う
- 【画面】③ 植物学を注入: 互生・パイプモデル。それでもスカスカ
- 【画面】④ 仕様書 × AI 画像監査: 互生・分枝比 0.6〜0.75・葉は枝から 20mm 以内を仕様書にし、Codex が画像を仕様と照合して PASS/FAIL＋数値指示。曖昧な違和感が数値の修正指示に変わった
- 【話者】人が初めて見るのは AI が「完成」と言った後。違和感は「この観点で見て」と観点で渡す

## 8. 検証の仕方

- 【話者】定点観測: AI が決めた同じビューポート・カメラから進捗を撮らせ、破綻と改善を比較（KOBATAKA）
- 【画面】固定アングルの反復: カメラを固定し変数（時間帯を 10 分刻みなど）だけ変えて並べ、差分は人間が判断
- 【話者】敵対的レビュー: 作業 AI とは別に、厳しい人格のツッコミ役サブエージェントを置いて定期監査。衝突・隙間・「木っぽくない」などを指摘させ、改善方法も提案させる。作業中の記憶を持たないので新鮮な観点になる
- 【画面】作例の規模表記: 「敵対レビュー 2 周」「レビュアー 11 系統」「検分画像 79 枚」「建築ゲート 20 本 PASS」「42 ゲートを毎回機械で検査」
- 【画面】「作る AI と検品する AI を分ける」
- 【画面】「全 PASS でも捨てる。『マネキン的』なら出さない」→ 数値ゲートの外側に人の品質判断を残す
- 【話者】人工物は破綻をコードで検証できる。キャラクターの曲線は人が OK/NG を都度渡す

## 9. Blender 側の前提・API の注意

- 【画面】ジオメトリノードのモディファイアー入力を外から変える書き方で 3 回間違えた:
  - ✗ `mod["Socket_2"] = 値`（4.x の定石）→ エラー
  - ✗ interface の `default_value` を変更 → エラーなしで無効（最悪。A と B が同一画像になっても気付かない）
  - ✓ `mod.properties.inputs.Socket_N.value`（5.x）
- 【事実】Blender 5.x の Python API では GN モディファイアーの入力が RNA プロパティ化され、`modifier.properties.inputs.<identifier>.value` で設定する（Blender 5.2 LTS のリリースノート参照。導入バージョンが 5.0 か 5.2 かは要確認）。https://developer.blender.org/docs/release_notes/5.2/python_api/
- 【画面】「AI の知識は古い。Blender の API 世代差で最初に転ぶ。対処は『実行して確認』を 1 手目にすること」
- 【画面】柵ジェネレーター: Curve to Points → Instance on Points ＋ Curve to Mesh。支柱間隔・高さ・半径をソケット化。ノードグラフ構築は一発成功
- 【画面】花火も GN: 空気抵抗つき弾道の閉形式解をフィールドで毎フレーム評価。シミュレーションゾーン不使用なので全フレーム決定論的で、レンダー再開が安全
- 【画面】モディファイアー＝Blender 内の「コード的な作り方」。手で押し出すより積んだ手順を書き換えるほうが AI は得意（柱 1 本 → Bevel → Subdivision → Array×2 軸、count 8→14 で回廊を作り直し、形は非破壊）
- 【画面】「決定論ビルド」「全部スクリプトから再ビルド可」: シーン全体をスクリプトで再生成できる状態に保つ

## 10. うまくいく題材・失敗する題材（2026-09-05 時点）

- 【画面】一発生成 12 種: 成功＝平歯車・らせん階段・本棚・宇宙船・ロボットアーム／半成功＝ワイングラス・落葉樹（葉なし）・ネオン看板／失敗＝配管ラック・人間の顔・犬・山岳地形 2km
- 【話者】得意: 数値で言い切れる形、繰り返し、角と水平の多い建築、ジオメトリノードで作る形（テクスチャまで貼る）。城は「日常的に見ないので多少破綻しても気付かれない」
- 【話者】苦手: 有機形状（連続曲面は数式で表しにくい）、部品の接続（配管が途中で途切れる、椅子の貫が脚につかない、骨格が欠落・浮遊）、物理量・時間順（花火で光より先に煙が出る）
- 【話者】GPT-6 Astra で有機形状が大きく改善。1 枚の絵からキツネのキャラクターを全身立体化。MCP 経由で粘土のように少しずつ形を出していた（posi_posi）
- 【話者】コンピューターユース（AI が画面とマウスを操作）の速度・正確性も上がった印象（KOBATAKA、SNS の初日の反応から。要確認）

## 11. 経験の蓄積

- 【画面】実践 → 成功・失敗・判断を記録 → LLM wiki → Recipe / Script / Skill → 次の制作。「モデルの追加学習ではなく、外部記憶を次回参照させる」
- 【話者】Web のノウハウは人間の手作業前提。コードで Blender を動かす AI 固有のつまずき（どのコードが通らないか、どのアプローチが快適か）を AI 自身に書き留めさせる
- 【話者】人間向けチュートリアル（YouTube・ブログ）を AI と一緒に解き、作法を記憶させる。マグカップはチュートリアルを読ませると中空・取っ手・カメラアングルが改善
- 【話者】大量生成: 幾何形状 1000 体（40 テーマ）を 100×10 ラウンドで。各ラウンド間に振り返りと仮説。所要時間も記録させると、最後の 100 体は最初より大幅に速い。【画面】「量産できることと、良いものを選べることは別」
- 【話者】効果はスピード（低品質で差し戻す回数が減る）と品質の安定（地雷を踏む回数が減る）
- 【話者】記憶は指示しないとされない。何を記憶するかの判断観点も渡す

## 12. 判断基準（人間と AI の分担）

- 【画面】人が握る: 発想・お題（AI に選ばせても採否は人）、寸法・レイアウト（決めなければ AI が最小コストで埋める）、専門知識の注入（本の丸背・チリ・小口は人が言うまで入らない）、検査基準の数値化（G1〜G6、一番時間を使う）、品質判断・責任
- 【画面】AI に渡す: 素形状・ディテール（bpy は全部 AI）、マテリアル・照明（指名すれば数値どおり。スキャン PBR を HDRI で BOX 投影）、検査の実行・修正
- 【話者】判断が AI／コードの中で閉じるか（任せられる）、人間の感性が効くか（人が持つ）で分ける
- 【話者】どこを完成とするか・責任の範囲は人が持つ。不気味の谷のような判断は人間の審美眼
- 【話者】人に残るのはディレクション力（何を作るか、どこを目指すか、途中の方向転換）
- 【画面】まとめスライド: 「AI を信じるな、検証プロセスを信じろ。流派が違っても構造は同じ」
- 【話者】Blender を知っている人ほど破綻に気付けるので、最初から高品質を出せる

## 13. 画像生成・動画生成との連携

- 【話者】固定カメラ×時間帯スタディのように、人間の判断の手前の選択肢を並べる作業は AI に向く
- 【話者】オニキスのマテリアル: Codex が画像生成でテクスチャを作り、Blender に適用し、実物写真と比べて改善。ノードでのサイズ調整も自動。ただし人の言葉のフィードバックも必要だった
- 【話者】モデル → 画像生成で光・質感を仕上げ → 動画生成、のリレー。動画化は「仕上げた静止画を動かす」か「Blender のカメラワーク動画をそのまま動画生成にかける」の 2 通り
- 【話者】ビューポートのキャプチャーを入力にマテリアル違いを 10 パターン画像生成 → 人が方向性を選ぶ → それをお手本に次の作業
- 【話者】レンダラーの光計算とは別物なので限界はあるが、雰囲気確認や用途次第では十分

## 14. 落とし穴

- 「実行できた」≠「反映された」（エラーなしで無効な API）。変化を画像や値で必ず確かめる
- AI の Blender API 知識は古い（4.x の書き方を使う）
- MCP の同期呼び出しのタイムアウト（2〜3 分）
- 何も指定しないとプリミティブ＋単色、見えない面は作らない、専門機能を使わない
- 接続・時間順・物理の破綻は人が想定しない形で起きる。やってみて確認する
- 自己レビューだけだと作業 AI の思い込みが残る → 別人格のレビュアー
- 記憶の無差別な蓄積は質を下げる
- 事前収録（9/5）時点の評価。モデル・ツールの優劣は 1 か月単位で変わる

## 15. 始め方（Skill の入口向け）

- 【画面】「自分が判断できる分野から始める」。専門分野の教材や作品研究を AI と一緒に解いてみる
- 【画面】Codex または Claude Code ＋ Blender MCP
- 【画面】まとめ: 自分が良し悪しを判定できる題材を、言葉で 1 個頼む。セットアップ手順・つまずき集・境界表は資料として配布（配布先は要確認）
